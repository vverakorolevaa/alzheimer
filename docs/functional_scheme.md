# Функциональная схема приложения Alzheimer

## Назначение

Приложение диагностирует стадию болезни Альцгеймера по двум источникам данных:
- **МРТ-биомаркеры** (объём мозга, измеренный программой FreeSurfer)
- **Клинические данные** (возраст, когнитивные тесты MMSE и CDR)

Результат: вероятность принадлежности пациента к одной из трёх стадий — **CN** (норма), **MCI** (ранняя стадия), **AD** (деменция).

---

## Команды приложения

```

      └── analyze             → DEG-анализ GSE138852 (исследовательский)
```

### Шаг 3 — Разделение данных

```
               ▼
  GroupShuffleSplit по subject_id
  ┌────────────────────────────────────────────────────────────┐
  │ ПРАВИЛО: все визиты одного пациента — только в TRAIN       │
  │          или только в TEST. Никогда не в оба сплита.       │
  │                                                            │
  │ Зачем: без этого модель «запомнит» конкретных людей, а     │
  │        не паттерны болезни — и даст завышенную точность.   │
  └────────────────────────────────────────────────────────────┘
  80% → Train      20% → Test
```

### Шаг 4 — Обучение трёх моделей

```
     Train
       │
       ├─────────────────────────────────────────────────────────┐
       │  Модель 1: MRI-only baseline                            │
       │  RobustScaler(X_mri)                                    │
       │  Linear(3→128) → ReLU → Dropout(0.3)                   │
       │  → Linear(128→64) → ReLU → Dropout(0.3) → Linear(64→3) │
       │                                               ↓         │
       │                                      P(CN), P(MCI), P(AD)│
       ├─────────────────────────────────────────────────────────┤
       │  Модель 2: Clinical-only baseline                       │
       │  StandardScaler(X_clin)                                 │
       │  Linear(6→128) → ReLU → Dropout(0.3)                   │
       │  → Linear(128→64) → ReLU → Dropout(0.3) → Linear(64→3) │
       │                                               ↓         │
       │                                      P(CN), P(MCI), P(AD)│
       ├─────────────────────────────────────────────────────────┤
       │  Модель 3: Gated Fusion (ОСНОВНАЯ)                      │
       │                                                         │
       │  X_mri ─► MRIEncoder                                   │
       │           Linear(3→256)→BN→ReLU→Drop                   │
       │           Linear(256→128)→BN→ReLU→Drop    e_mri (128)  │
       │           Linear(128→128)  ─────────────────────┐      │
       │                                                  ▼      │
       │  X_clin─► ClinicalEncoder               GatedFusion    │
       │           Linear(6→64)→ReLU→Drop        gate=σ(W·      │
       │           Linear(64→128)    ───────────► [e_mri;e_clin])│
       │                              e_clin(128) fused=gate·    │
       │                                          e_mri+(1-gate)·│
       │                                          e_clin         │
       │                                            ↓            │
       │                               Classifier  128→64→3      │
       │                                            ↓            │
       │                                  P(CN), P(MCI), P(AD)   │
       └─────────────────────────────────────────────────────────┘
```

## Gated Fusion — ключевой механизм

```
  Для каждого пациента:
  ┌─────────────────────────────────────────────────────┐
  │  gate = sigmoid( W · [e_mri ; e_clin] )             │
  │                                                     │
  │  gate → 1: модель доверяет МРТ                      │
  │  gate → 0: модель доверяет клиническим данным       │
  │                                                     │
  │  fused = gate · e_mri  +  (1 − gate) · e_clin       │
  └─────────────────────────────────────────────────────┘

  Пример: пациент с ранним MCI
    - МРТ-изменения ещё незначительны → gate низкий
    - MMSE снизился → клиника весомее
    → gate автоматически сдвигается к клиническим данным
```

## Меры против переобучения

```
  Проблема: ~500 пациентов, тысячи параметров — риск запоминания

  Решения:
  ┌──────────────────────┬────────────────────────────────┐
  │  Donor-level split   │ один пациент только в train    │
  │                      │ или только в test              │
  ├──────────────────────┼────────────────────────────────┤
  │  Weighted Loss       │ компенсация дисбаланса классов │
  ├──────────────────────┼────────────────────────────────┤
  │  Dropout(0.3)        │ 30% нейронов выключены в train │
  ├──────────────────────┼────────────────────────────────┤
  │  BatchNorm           │ стабилизация активаций         │
  ├──────────────────────┼────────────────────────────────┤
  │  L2-регуляризация    │ weight_decay = 1e-4            │
  └──────────────────────┴────────────────────────────────┘
```

## Исследовательский пайплайн: analyze (дополнительный)

```
  GSE138852 (Mathys et al., 2019 — Nature)
  80,000+ клеток мозга, 80 пациентов (48 с AD, 32 здоровых)
        │
        ▼
  DataLoader → AnnData (клетки × гены)
        │
  Preprocessor
  - фильтрация низкокачественных клеток
  - нормализация по числу прочтений
  - log1p-преобразование
        │
  GeneAnalyzer
  - Mann-Whitney U тест для каждого гена в каждом типе клеток
  - BH FDR-коррекция на множественные сравнения
  - порог: FDR < 0.05, |log2FC| > 1.0
        │
  Visualizer
  - barplot: число DEG по типам клеток
  - volcano: log2FC vs -log10(FDR) для каждого типа клеток
  - heatmap: топ-50 генов
  - UMAP: типы клеток в пространстве генной экспрессии
        │
  EnsembleClassifier
  - три головы: Expression / Composition / Gene2Vec
        │
  EnrichmentAnalyzer
  - Enrichr API: GO, KEGG — биологические пути
```
